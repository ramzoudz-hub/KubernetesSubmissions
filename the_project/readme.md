# The Project – Kubernetes Exercise 1.2

## 1. Create a Kubernetes Cluster

We started by creating a local Kubernetes cluster using **k3d**:

```bash
k3d cluster create mycluster
```

This creates a Kubernetes cluster named `mycluster`.

## 2. Build the Docker Image

First, we created a `Dockerfile` for our Node.js application.

Then, we built the Docker image locally:

```bash
docker build -t the-project:latest .
```

The image is now available locally.

**Note:** We have two options for using the image:

- Push it to Docker Hub so it can be accessed remotely.
- Keep it locally and use it directly.

For this exercise, we decided to use the local image.

Since we are using k3d, we need to import the image into the cluster:

```bash
k3d image import the-project:latest -c mycluster
```

## 3. Create a Kubernetes Deployment

Next, we deployed our application using `kubectl create deployment`:

```bash
kubectl create deployment the-project --image=the-project:latest --dry-run=client -o yaml | kubectl apply -f -
```

**Explanation:**

- `kubectl create deployment`: Creates a Deployment.
- `the-project`: The name of the Deployment.
- `--image=the-project:latest`: Specifies the Docker image.
- `--dry-run=client -o yaml`: Generates the Deployment YAML without immediately creating the resource.
- `kubectl apply -f -`: Applies the generated YAML to the cluster.

To make sure Kubernetes uses the local image without trying to pull it from a registry, edit the Deployment:

```bash
kubectl edit deployment the-project
```

Under `spec.template.spec.containers`, add:

```yaml
imagePullPolicy: Never
```

## 4. Verify the Deployment and Pod

To check whether our Deployment was created successfully:

```bash
kubectl get deployments
```

To check the Pod managed by the Deployment:

```bash
kubectl get pods
```

If everything is working correctly, we should see the `the-project` Pod with a `Running` status.
